# 研究分享路线：首批实物与后续问题

这份路线图区分当前提供的内容与后续研究方向，不是完整产品开源承诺，也不承诺未完成实验的日期或结果。

| 内容 | 已提供的形态 |
| --- | --- |
| TCP / OCR / 表解析 | 精确选定的历史小模块、适配说明和人工测试 |

## 后续批次：先形成证据，再选择分享

后续热修版本形成更多可验证的实现和运行证据后，再评估以下内容。没有正在运行的深度实验，
也不因本路线图而提前启动私有产品开发或改变采集链路。

1. **身份与符号实验**：优先考虑自有构建、模块身份、地址、符号配对与正反例。
2. **C++观察层对照**：在自有host与合成事件上实现producer/consumer，再做行为等价和同输入基准。
3. **生命周期与数据适配**：ownership/退出协调、事件重放、录制比较器等，按成熟度和输入完整性选取。
4. **更多历史数据**：仅在能回答新问题时增加少量有价值的聚合或结构统计，不为数量补表。

真实bundle适配和旧实战回放需要先装配精确且适合分享的输入；它们不是首批内容的隐含依赖。
具体对象、工作量和完成条件会在选中项目后说明，不把所有未来题目绑定为一次大任务。

## 展示结果，不必连带公开整个实现

适合某个案例时，可以在维护者环境中运行选定源码与合格样本，公开必要的输入描述、
中间值、最终结果和实际UI截图，再配小段通用代码或概念图解释处理过程。
截图只能证明其对应版本、输入和状态的显示结果，不能代替算法验证或源码开放。

- 真实运行、历史摘要和合成模型分别标记；不拿虚构图冒充产品实机，不把旧截图当新实验。
- 数据字段、单位、处理步骤与最终UI字段要能对应；只选解释问题所需的字段，不输出整份诊断。
- 截图去除无关身份/路径等信息，并保留输入/版本的可恢复记录；底层原件不靠覆盖来清理。
- 非线性关系适合结果曲线，状态/字段问题适合对照表，真实交互问题再使用实际UI截图。

更多题目见[贡献入口](CONTRIBUTION_IDEAS.zh-CN.md)。后续是否开放更完整模型与参数，是独立的产品资产选择，
不因为已有教学材料或某个函数年代较早而自动发生。
