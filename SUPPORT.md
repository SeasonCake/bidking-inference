# Support

Use GitHub Issues for reproducible problems with the public library, synthetic examples,
documentation, or non-sensitive Windows-release download/startup/visible symptoms.
Select the component and include its commit/version, OS/runtime, exact command or steps,
minimal synthetic input/event order, expected invariant, actual result and repeatability.

The [failure-workflow cases](docs/FAILURE_WORKFLOWS.md) show how to report file-save,
refresh-order and staged-result problems without a private application or service.

Do not attach private product diagnostics, credentials, captured traffic, proprietary
tables, or real user data. Account-specific product support and full diagnostic files
use the maintainer's existing private support channels linked from the README.
Public reports do not imply access to the product's private implementation or an account
policy change. Use private security reporting for vulnerabilities.
